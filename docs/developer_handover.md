# Developer Handover & Architecture Guidelines

Welcome! This document outlines the current state of the web scraping pipeline, what has been successfully implemented, and strict guidelines for the next phase of development.

## 1. What Has Been Built (DO NOT TOUCH)

We have successfully built a robust, bot-bypassing "Domain Discovery and Scraping Pipeline". The following files and setups are tested, working perfectly, and **MUST NOT BE MODIFIED**:

- **`backend/searXNG/` (Docker Setup)**: A local SearXNG instance used for unlimited, unblocked domain discovery.
- **`backend/search_engine.py`**:
  - `find_manufacturer_domain()`: Dynamically finds the exact official manufacturer domain using SearXNG.
  - `search_exact_product()`: Performs a strict `site:{domain} "{MPN}"` search to find the exact product URL.
- **`backend/scraper.py`**: Implements the **"Everything Bucket"** approach using Playwright. Because modern sites (like Diablo Tools) are SPAs that hide data in scripts or meta tags, this scraper bypasses visual filtering and aggressively extracts:
  1. `<meta>` descriptions and titles.
  2. `application/ld+json` schemas.
  3. `__NEXT_DATA__` / `__INITIAL_STATE__` React/Vue payloads.
  4. Visible body text.
- **`backend/pipeline.py`**: The orchestrator that takes a row from the CSV, runs the search engine, runs the scraper, and dumps the raw text into `scraped_output_<MPN>.txt`.

> [!WARNING]
> **DO NOT modify `search_engine.py`, `scraper.py`, or the SearXNG configuration.** They are perfectly tuned to bypass anti-bot mechanisms and capture hidden SPA data. Any changes could break the discovery logic or cause the scraper to get blocked.

## 2. What Is To Be Done Next (Your Task)

Your job is to take the massive text dump generated by `pipeline.py` (e.g., `scraped_output_DCB518ASTS06G.txt`) and extract the specific product attributes (Dimensions, Weight, Material, etc.) required for the final CSV.

### The Plan: Tiny LLM Extraction (Phase 3)
Instead of using massive cloud LLMs (like GPT-4) which are slow and prone to hallucination, you must implement a **Tiny Specialized Model** specifically designed for structured Information Extraction.

We have identified two state-of-the-art options for this:

1. **GLiNER (Generalist Lightweight NER)**: 
   - A tiny, blazing-fast local model trained for zero-shot entity extraction.
   - It does not generate text; it purely acts as a highlighter. You prompt it with attributes like `"voltage"`, `"material"`, `"height"`, and it extracts the exact match from the "Everything Bucket" text.
2. **NuExtract**: 
   - A 1.5B parameter local model designed *exclusively* for filling out JSON templates based on raw text.
   - You provide a JSON schema of the required attributes, feed it the text, and it perfectly fills out the schema locally.

### Your Guidelines for Implementation:
1. **Create a new file** (e.g., `backend/extractor.py`) for your Tiny LLM logic.
2. **Read the `.txt` output**: Your script should take the text from `scraped_output_<MPN>.txt` as its input.
3. **Format the Output**: Parse the extracted data into a strict JSON dictionary that matches the column requirements for the final delivery CSV.
4. **Integration**: Once your `extractor.py` works on the sample `.txt` file, you can import it into `pipeline.py` and run it at the very end of the `process_row()` function.
